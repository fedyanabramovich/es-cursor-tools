# Блоки ISIVR

Имена типов ниже предназначены для поля `type` в `isivr_save_module`. `params` — объект
`ExtData`; регистр имён полей значим. Общие поля `name`, `description` и логирование
задаются в данных блока. `BeginCellID`, идентификаторы портов и XML управляются MCP:
не генерируй их.

Повторяющиеся значения:

- `{IsManual, Value}` — `IsManual: true` означает литерал в `Value`, `false` означает
  имя переменной модуля (`ANI`, `DNIS` и любая заведённая переменная).
- `{IsGlobal, Custom}` — `IsGlobal: true` берёт серверную настройку, `Custom` тогда пустой.
  `IsGlobal: false` подставляет своё значение в `Custom`.
- ID звука, функции, календаря, списка, категории и таблицы — число, которое вернул API.
  Не выдумывай его.

Файлы дизайнера `SMSSending` и `Code` в типы блоков не входят: сервер такой блок не примет.

## Управление сценарием

### `Start` — Начало

Единственная точка входа модуля. Обязателен ровно один блок. Специальных параметров нет.
Единственный выход `""`.

### `End` — Конец

Завершает текущий модуль. Если приложение вызвано без передачи управления, возвращает
выполнение родителю. Обязательный логический терминал; выходов нет.

### `EndCall` — Сброс

Завершает вызов и всю цепочку приложений. `params.Code` — символьное имя причины,
не число. Обычное завершение: `"NORMAL_CLEARING"` (Q.850 16). Выходов нет.
Не заменяй им `End`, если требуется возврат в родительское приложение.

Имена, которые принимает дизайнер: `UNALLOCATED_NUMBER` (1), `NO_ROUTE_TRANSIT_NET` (2),
`NO_ROUTE_DESTINATION` (3), `NORMAL_CLEARING` (16), `USER_BUSY` (17),
`NO_USER_RESPONSE` (18), `NO_ANSWER` (19), `SUBSCRIBER_ABSENT` (20),
`CALL_REJECTED` (21), `NUMBER_CHANGED` (22), `DESTINATION_OUT_OF_ORDER` (27),
`INVALID_NUMBER_FORMAT` (28), `FACILITY_REJECTED` (29), `NORMAL_UNSPECIFIED` (31),
`NORMAL_CIRCUIT_CONGESTION` (34), `NETWORK_OUT_OF_ORDER` (38),
`NORMAL_TEMPORARY_FAILURE` (41), `SWITCH_CONGESTION` (42),
`REQUESTED_CHAN_UNAVAIL` (44), `FACILITY_NOT_SUBSCRIBED` (50),
`OUTGOING_CALL_BARRED` (52), `INCOMING_CALL_BARRED` (54),
`BEARERCAPABILITY_NOTAUTH` (57), `BEARERCAPABILITY_NOTAVAIL` (58),
`SERVICE_UNAVAILABLE` (63), `BEARERCAPABILITY_NOTIMPL` (65),
`FACILITY_NOT_IMPLEMENTED` (69), `SERVICE_NOT_IMPLEMENTED` (79), `CRASH` (700),
`SYSTEM_SHUTDOWN` (701), `ALLOTTED_TIMEOUT` (802), `USER_NOT_REGISTERED` (806).

`EndScript` — старое API-имя сброса. Для новых схем используй `EndCall`; сохраняй
`EndScript` только при точечном редактировании существующей схемы.

### `Marker` — Метка

Якорь для локального повторного входа в участок схемы. Имеет выход `""`, но не обычный
входящий порт. В паре с `GoTo` уменьшает длинные обратные стрелки. Если метка —
единственный вход в точку, через неё идут все переходы в эту точку: у каждого
источника свой ближайший `GoTo`, а к самой точке подключён только выход метки.
Метка стоит прямо над целью по центру: выход у неё внизу, поэтому из метки сбоку
получается ломаная стрелка. Блоку с несколькими входами метка нужна всегда. Так убирается
переход вдоль одного ряда и стрелка, которой иначе пришлось бы идти сквозь блоки
промежуточного уровня.

### `GoTo` — Переход к метке

Безусловно передаёт управление выбранному `Marker`, выходов нет.
Соседние блоки одного ряда, которые ссылаются на одну и ту же метку, делят один
такой переход: их выходы сходятся в него.
`params.MarkerBlockCellID` — числовой CellID метки. Ребра из `GoTo` нет: переход
записан в параметре. Ребра в `Marker` нет: у метки нет входа, такое ребро
сохранение отклоняет.

### `InfinityWait` — Бесконечное ожидание

Останавливает последовательное выполнение до внешнего события телефонии. Специальных
параметров и выходов нет. Типичен после постановки в очередь, асинхронного запуска
приложения или ветки `SetTimer.Before`.

### `TransferToApp` — Перевод на приложение

Запускает другое приложение:

- `ApplicationDataID` — DataID целевого приложения, число;
- `TransferControl` — передать линию дочернему приложению, по умолчанию `true`;
- `ContinueIfError` — продолжать сценарий при ошибке запуска, булево, по умолчанию `true`;
- `TransmittedParams` и `ReturnedParams` — `[{Name, Value}]`. Пустое имя или значение
  не проходит валидацию. Имена совпадают с параметрами дочернего приложения.

При `TransferControl: true` родитель не получает управление обратно. При `false`
подключи выход `""` и выбери поведение при ошибке осознанно.

### `Transfer` — Переход к модулю (устарел)

Переход к другому модулю того же приложения, `params.ModuleID` — ID модуля.
Модули больше не поддерживаются: в новых схемах этот блок не используй, MCP его
отклонит. Встречается только в старых схемах; при правке такого блока сохрани его как есть.
Вместо него встраивай логику через `Marker`/`GoTo` или вызывай отдельное приложение
через `TransferToApp`.

## Телефония и контакт-центр

### `AnswerCall` — Ответить

Отвечает на входящий вызов (200 OK). Специальных параметров нет, выход `""`.
Обычно предшествует звуку, меню, вводу или переводу в КЦ.

### `CC` — КЦ

Исходящий вызов на номер. Это не очередь: очередь — `CC_IPN`. `Transfer` — устаревший
переход к модулю, для дозвона его не используй.

Рабочий `params`:

```json
{
  "ANumber": {"IsManual": false, "Value": "ANI"},
  "BNumber": {"IsManual": true, "Value": "20000"},
  "Duration": 30,
  "UUI": {"IsManual": false, "Value": "DNIS"},
  "DirectionType": "2",
  "HandleCallRemoteMedia": true,
  "OutputsData": []
}
```

`Duration` — секунды дозвона, от 10 до 1000. Пустые `ANumber`, `BNumber`, `UUI`
или пустой `DirectionType` валидация отклоняет. `DirectionType` бери из
`Data_GetDirectionTypeList` (`{"q":""}`). На стенде встречались `"2"` (локальный
номер), `RP_JAICP` (транк бота) и `TELEXTREG_SIPPROXY`.

`OutputsData` — дополнительные выходы по SIP-коду: `{ID, Value}`. `Value: true`
добавляет ребро с `output`, равным коду (`"404"`, `"486"`, `"603"` и остальные
коды 400, 401, 403, 407, 408, 480–484, 488, 500–504, 600, 604, 606–608).
Пока все `Value` ложны, выходов два: `disconnected` и `fail`. Обе ветви должны
завершаться или явно восстанавливаться.

В старых модулях в `ExtData` встречаются `GNumber`, `SendSigInfo` и `UuiInSigInfo`.
Текущий блок их не читает. При правке такого модуля сохрани эти ключи как есть.

### `CC_IPN` — КЦ IPN

Ставит вызов в очередь IPN. Поля, которые читает сервер:

- `ANumber`, `BNumber`, `UUI`, `AgentLogin`, `AgentTimeout`, `PreferredAgentActive`:
  `{IsManual, Value}`. У предпочтительного агента значение `"true"` или `"false"`;
- `SkillRoute`: `{IsManualSkill, IsCustomSkill, SkillValue, IsManualRoute, IsCustomRoute, RouteValue}`.
  Навык проверяй через `Data_GetSkillList` (`{"q":"90000"}`). Маршрут —
  `Data_GetRouteList`, тело `{skill, q, ignoreEmptySkill}`: без `skill` список пуст,
  если `ignoreEmptySkill` не `true`;
- `HandleCallRemoteMedia` — early media, по умолчанию выключен;
- `StopRecordConnectingAgent` — остановить запись после ответа агента, по умолчанию `true`.

`Skill` и `Route` в старых схемах — прежняя пара полей. Новый блок заполняет
`SkillRoute`. При правке старого блока не удаляй `Skill` и `Route`, если они уже есть.

Выход `enqueued` означает постановку в очередь; обычно ведёт к звуку/EWT/таймеру.
Выход `connected` означает ответ агента; обычно ведёт к `InfinityWait`.

### `StopChannel` — Стоп-канал

Останавливает активные каналы линии, включая асинхронный звук. Специальных параметров
нет, выход `""`.

### `SIPHeader` — Получить SIP-заголовок

Читает один заголовок входящего SIP-вызова в переменную модуля.

- `HeaderName` — 1–100 символов: латиница, цифры, `.`, `_`, `-`;
- `ResultVariable` — имя уже существующей строковой переменной.

Для нескольких заголовков используй последовательность блоков. Выход `""`.

## Звук и ввод

### `Sound` — Звук

Проигрывает один звук.

- `SoundGroupID` — DataID звука, число. Пустое значение не проходит валидацию;
- `PlayType` — `"Repeat"` (доиграть целиком, по умолчанию) или `"Duration"`
  (играть не дольше заданного времени);
- `RepeatCount` — число повторов при `"Repeat"`, от 1 до 100;
- `Duration` — миллисекунды при `"Duration"`, не 0;
- `TermDigits: {IsGlobal, Custom}` — клавиши прерывания;
- `Async` — фоновое проигрывание, по умолчанию `false`.

При `Async: false` выход `""` срабатывает после звука. При `true` предусмотрите
`StopChannel` либо другое событие остановки, если звук не должен продолжаться.

### `DtmfMenu` — Голосовое меню

Проигрывает звуки и ветвится по DTMF.

- `Sounds` — массив DataID звуков. Нужен он или `SoundGroupID`: пустые оба
  не проходят валидацию;
- `OutputsData` — 12 элементов `{ID, Value}` для `1..9,0,*,#`. `Value: true`
  означает, что кнопка подключена ребром;
- `GoBackButton` — клавиша назад, по умолчанию `"#"`. Если та же клавиша есть
  в выходах, валидация предупреждает: «назад» важнее выхода;
- `NoMatchSound`, `NoInputSound`: `{IsGlobal, Custom}`;
- `NoMatchCount`, `NoInputCount` — попытки, при своём значении от 0 до 100;
- `MaxTime` — таймаут, при своём значении от 0;
- `InputLockoutTime` — блокировка ввода в секундах, при своём значении от 0 до 600.

Рёбра по кнопкам используют `output: "1"` … `"9"`, `"0"`, `"*"`, `"#"`.
Всегда подключай `NoInput` и `NoMatch`. MCP синхронизирует `OutputsData.Value`
с реально подключёнными кнопками.

### `InputField` — Ввод данных

Собирает и проверяет последовательность DTMF.

- `SoundGroupID` — подсказка, DataID;
- `ResultVariable` — существующая строковая переменная;
- `ValidationMode`: `0` длина (`MinDigits`/`MaxDigits`, каждое от 1 до 100,
  максимум не меньше минимума), `1` диапазон в `Range`, `2` regex .NET
  в `RegularExpression`;
- `NoMatchSound`, `NoInputSound`, `NoMatchCount`, `NoInputCount`, `MaxTime`,
  `MaxIDDTime`, `InputLockoutTime` — `{IsGlobal, Custom}`. Свои попытки от 0 до 100,
  блокировка ввода от 0 до 600 секунд, оба таймаута не меньше 1.

Повтор ввода в дизайнере — `*`, подтверждение — `#`. Это не поля `params`.
Выход `""` — успешный ввод, `NoInput` — таймаут, `NoMatch` — исчерпана обработка ошибок.

### `Record` — Запись звука

Записывает входящую линию.

- `AudioBeforeRecord`, `AudioAfterRecord` — DataID звуков до и после записи, либо `null`;
- `RecordDuration` — секунды, от 1 до 300, по умолчанию 30;
- `PathVariable` — имя переменной с путём файла. В пути допустимы шаблоны
  `%Y`, `%m`, `%d`, `%H`, `%M`, `%S`, `ANI`, `DNIS`, `GUCID`, `SCRIPTID`;
- `TermDigits: {IsGlobal, Custom}` — клавиши остановки записи.

Выход `""`.

## Логика и данные

### `Condition` — Условие

Ветвится по выражениям.

- `Condition.ConditionText` — текст выражения, например `S = "1"` или `DNIS like "800____"`;
- `Condition.Name` можно оставить пустым, `Condition.ConditionStruct` — `null`;
- `AdditionalConditions` — дополнительные именованные условия;
- `OutputsData` — сохраняй структуру существующего блока.

Основные выходы: `true` и `false`; дополнительные используют строковый ID условия.
Поддерживаются `and`, `or`, `not`, сравнения, арифметика и `like`. Переменная
должна уже существовать в модуле. Ветви располагаются в порядке условий,
`false` — последняя fallback-ветвь.

### `Function` — Функция

Вызывает заранее созданную HTTP(s)-функцию из справочника «Функции». Это основной
механизм интеграции приложения с внешними системами: получение данных клиента,
проверки, маршрутизационные решения, EWT. Перед использованием изучи доступные функции
и их параметры (см. `SKILL.md`, «Интеграции через функции»).

- `FunctionID` — ID версии функции из `Function_GetFunctionsSelectData`
  или `Application_GetFunction`;
- `InputParams` и `OutputParams` — `[{ID, Value:{Type, Name, Value}}]`.
  `ID` — ID параметра функции, `Value.Name` — его имя, `Value.Type` — тип,
  `Value.Value` — литерал или имя переменной модуля того же типа.

Входы и выходы связывай только с переменными совпадающего типа. Выход блока `""`.
Не создавай функцию и не меняй её версию без прямого запроса.

### `DynamicParams` — Динамические параметры

Загружает категорию внешних параметров без перекомпиляции приложения.
`CategoryID` — существующая категория. Выход `""`. После блока используй имена и типы,
которые реально предоставляет категория.

### `DataChange` — Изменение данных

Изменяет значения динамической категории.

- `CategoryID` — ID категории из `DynamicParams_GetGroupsSelectData`;
- `Params`: `[{ParamName, Value:{IsManual, Value}}]`. Имя параметра берётся из
  `DynamicParams_GetCategoryParamsSelectData`, тело `{id}` категории.
  Один параметр не повторяется. `IsManual: false` требует переменную того же типа.

Выходы: `Successfully` и `Unsuccessfully`. Ошибочную ветвь нельзя оставлять без
осмысленного завершения. Это глобально влияющая операция — применяй только по явному
требованию.

### `ListCheck` — Проверка списка

Ищет ключ в динамическом списке и при необходимости сохраняет значение.

- `KeyToCheck: {IsManual, Value}` — литерал не длиннее 100 символов либо имя переменной;
- `ListID` — ID списка из `DynamicLists_GetListSelectData`;
- `ResultVariable` — строковая переменная для найденного значения либо пусто, тогда поле не пишется.

Выходы: `Contain` и `NoContain`.

### `DefRouting` — Маршрутизация

Ищет параметры маршрутизации по DEF/B-номеру.

- `RoutingTableID` — ID таблицы из `RoutingTable_GetGroupsSelectData`;
- `DefNumberVariable` — строковая переменная ключа, по умолчанию `"DNIS"`;
- `SkillVariable`, `RouteVariable` — строковые переменные результата,
  по умолчанию `"DFR_Skill"` и `"DFR_Route"`;
- `EwtAppVariable` — переменная ID EWT-приложения, по умолчанию `"DFR_EwtApp"`.

Эти четыре переменные должны существовать в модуле.

Выход `""`; типичный следующий блок — `CC_IPN`.

## Время и ожидание

### `SetTimer` — Установка таймера

Запускает периодический/одноразовый таймер.

- `TimerID` — идентификатор. Список дизайнера `0..23`, сервер принимает `0..63`;
- `TimeOut` — миллисекунды, не меньше 100;
- `Count` — число срабатываний, не меньше 1;
- `SkipOutputAfter` — битовая маска, когда не выполнять `After`:
  `1` входящий соединён, `2` неудачный вызов, `4` в очереди,
  `8` исходящий соединён, `16` отключён. `0` — не пропускать.

Выход `Before` выполняется сразу, `After` — по срабатыванию. Частый шаблон:
`Before -> InfinityWait`, `After -> EndCall` или обработчик таймаута.

### `ResetTimer` — Сброс таймера

Сбрасывает ранее установленный `SetTimer`. Выход `""`.

- `ResetType` — `"ID"` (по умолчанию) или `"Block"`;
- `TimerID` — тот же номер, что у `SetTimer`, когда `ResetType` равен `"ID"`;
- `TimerBlockCellID` — CellID блока `SetTimer`, когда `ResetType` равен `"Block"`.

### `Calendar` — Календарь

`params.CalendarID` — id календаря типа 1 (рабочие часы по дням недели).
Как получить и создать календарь — в [workflow.md](workflow.md), раздел «Календари».

Выход `WorkTime`: у сегодняшнего дня недели есть интервал, и текущее время внутри
него, включая границы. Выход `OffTime`: интервала нет или время снаружи.
День недели: 0 — воскресенье, 6 — суббота. Календарь с интервалом на всю
сутки (`0..864000000000` тиков) — это круглосуточный режим, а не ночное окно.

### `HolidayPeriod` — Нерабочее время

`params.CalendarID` — id календаря типа 2 (конкретные даты). Выходы называются
так же, как у `Calendar`, смысл другой.

Выход `OffTime`: сегодняшняя дата есть в списке, и текущее время внутри интервала
этой даты, включая границы. Это «сейчас нерабочий период». Выход `WorkTime`:
даты нет или время снаружи интервала.

Даты в ISIVR конкретные, с годом. Правило «каждый год 28 апреля» записывается
отдельной строкой на каждый год. Пустой список никогда не даёт `OffTime`.

### `PlayEWT` — Озвучить EWT

Озвучивает оценку ожидания и проигрывает музыку.

- `Variable` — имя целочисленной переменной EWT;
- `WaitMusicSoundGroupID` — DataID музыки ожидания;
- `Conditions`: `[{Treshold:{IsManual, Value}, AudioGroupDataID, Timer}]`.
  Порог, звук и таймер обязательны в каждой строке. `AudioGroupDataID` — DataID.

Условие порога трактуется как `EWT <= threshold`; располагай пороги по возрастанию.
Выход `""`.
